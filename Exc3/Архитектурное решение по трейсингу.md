## Анализ архитектуры в конексте планирования трейсинга

В системе наблюдаются сложности с поиском ошибок в процессе обработки заказов, а также непонятные ситуации с зависанием заказов между сервисами. В данном случае поможет разобраться с проблемами система трейсинга. Будем внедрять сервис Jaeger на основе платформы наблюдения OpenTelemetry.

На основе анализа представленной C4-диаграммы, можно выделить следующие сервисы для внедрения трейсинга:
1. Shop API
Заказ приходит из веб-приложения и может затеряться внутри или после сервиса ShopAPI

3. CRM API
Сервис CRM API - может долго генерировать список заказов, необходимо отследить причины задержки отображения списка.

4. MES API
Передает заказы Операторам на производство, однако может задерживать выдачу или "терять" заказы.

**Список данных, которые должны попадать в трейсинг:**
Контекст телеметрии:
- статическая информация о ресурсе: имя сервиса, окружение и тд.
- динамическая информация: идентификаторы эндпоинтов
Основые атрибуты: `trace_id`, `span_id`


## Мотивация
Трейсинг - это метод отслеживания прохождения запросов по сервисам ИТ-системы. Трейсинг помогает быстро находить причины возникающих проблем и ошибок. Трейсинг позволяет посмотреть сколько, где и с какими параметрами прошёл запрос. 
Отдельным преимуществом является возможность просмотра контектс ошбики или исключения. Передача контекста позволяет нижестоящему приложению восстановить информацию о предыдущих операциях и в итоге собрать полную распределённую трассировку, охватывающую все этапы обработки запроса.

Метрики, на которые может положительно повлиять внедрение трейсинга:
- Повышение метрик RPS для полного прохождения обработки заказов.
- Снижение latency по обработке комплексных запросов
- Более быстрое решение проблем и повышение надёжности системы. В результате - уменьшение времени простоя системы и снижение потерь от простоев.
- Повышение быстродействия системы и распределение ресурсов. За счет отслеживания проблемных мест обработки запроса можно повысить быстродействие и тем самым увеличить скорость работы всей системы.
- Повышение удовлетворённости пользователей. Улучшение пользовательского опыта за счет повышения быстродействия и отказоустойчивости всей системы.
